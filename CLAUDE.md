# CLAUDE.md - Agent Instructions & Architecture Bible

## Purpose & Architecture
**GitResume** is a CLI-first tool for analyzing repositories and generating resume artifacts.
- **Core Principle**: All processing (clone, scan, LLM, parse) happens in the CLI and produces immutable artifacts in `artifacts/`.
- **Web Dashboard**: STRICTLY read-only. It only visualizes artifacts generated by the CLI. No heavy processing or database logic in the web layer.
- **Packaging**: Cross-platform single-file binaries (Windows, macOS, Linux) via PyInstaller. Source of truth is `pyproject.toml` (managed by `uv`).

## Artifact Spec
Every run produces a bundle in `artifacts/<run_id>/`:
- `manifest.json`: Metadata, version info, inputs, hashes of outputs.
- `repo.json`: Raw repository metrics.
- `analysis/`: Intermediate analysis files.
- `resume/`: Generated resume (JSON/MD).
- `logs/`: Run logs (secrets redacted).

## Development Environment
We use `uv` for dependency management.

### Commands
- **Sync env**: `uv sync`
- **Run CLI**: `uv run gitresume --help`
- **Run Tests**: `uv run pytest`
- **Lint/Format**: `uv run ruff check .` / `uv run ruff format .`
- **Type Check**: `uv run pyright`
- **Build Binary**: `uv run python scripts/build.py` (or via Makefile)
- **Start Web**: `uv run gitresume web`

## Coding Conventions
- **Python**: 3.10+
- **Style**: Follow `ruff` defaults.
- **Type Hinting**: Strict typing required. Use `typing` module or standard types.
- **CLI**: Use `typer` + `rich` for all terminal output.
- **Errors**: Catch exceptions and print friendly `rich` error panels. Avoid raw stack traces in CLI (log them to file).
- **Imports**: Absolute imports preferred (`from gitresume_core import ...`).

## Security Rules
1. **Redaction**: NEVER log API keys, tokens, or auth headers to console or files.
2. **Input Validation**: Validate all file paths and URLs.
3. **Dependencies**: Pin all dependencies with hashes via `uv.lock`.

## Release Checklist
1. Bump version in `pyproject.toml` and `src/gitresume_core/__init__.py`.
2. Run `make test` (or `just test`).
3. Commit with `chore: bump version to X.Y.Z`.
4. Push tag `vX.Y.Z`.
5. CI will build and upload binaries.

## Agent Protocol
- **Proactive**: Fix bugs immediately if seen.
- **Atomic**: One logical change per commit.
- **Verification**: Run tests after changes.
