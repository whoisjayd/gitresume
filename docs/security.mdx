# Security

GitResume is designed to keep provider secrets and GitHub tokens out of task payloads, SSE events, and API responses.

## Secret handling

- `.env` is ignored and must not be committed.
- GitHub tokens are handed to workers through Redis one-time storage rather than Taskiq payloads.
- Ephemeral `providerApiKey` values are stored one-time in Redis and popped by the worker.
- Saved BYOK secrets are encrypted at rest with `SETTINGS_ENCRYPTION_KEY` and are never returned to the dashboard.
- Saved key responses contain metadata only: id, provider, label, optional model, timestamps, and active state.

## Session cookies

The app exposes cookie controls through:

- `SESSION_COOKIE_HTTPS_ONLY`
- `SESSION_COOKIE_SAME_SITE`
- `SESSION_COOKIE_MAX_AGE_SECONDS`

When `SESSION_COOKIE_HTTPS_ONLY` is unset, production mode uses HTTPS-only cookies.

## Worker failures

Worker code emits generic public failure messages and safe logs. Secrets are not included in task payloads, SSE responses, API responses, or frontend retry state.

## Repository access

Private clone operations use safe token handoff and avoid embedding tokens in git command arguments. Repository processing limits are controlled by `MAX_REPO_SIZE_MB` and `MAX_REPO_FILES`.

## Repository analysis pipeline

Generation jobs follow the worker pipeline in `gitresume.workers.generation_tasks`:

1. Validate repository access with `GitHubRepositoryService.validate_access`.
2. Clone into a temporary checkout with `RepositoryCheckoutService`.
3. Emit the `classifying-packing` analysis event and build packed context with `RepositoryIngestionService`.
4. Select credentials in this order: one-time `providerApiKey`, OAuth account token for OAuth models, compatible saved BYOK through `RedisProviderKeySelector`, then server environment provider keys handled by LiteLLM.
5. If `ENABLE_GUIDED_ANALYSIS=true`, emit `guided-evidence-investigation` and let `RepositoryInvestigationService` use repository-bounded tools: traversal, glob, read, and fixed-string search. The tools reject paths that escape the checkout root.
6. Generate the resume with `ResumeGenerationService` and store the final state in Redis.

## Guided contribution scope

Author-scoped evidence requires both `ENABLE_GUIDED_ANALYSIS=true` and `ENABLE_CONTRIBUTION_ANALYSIS=true`. A request can include `analysisAuthor` and `analysisDays`; if `analysisDays` is omitted, `CONTRIBUTION_ANALYSIS_DEFAULT_DAYS` is used. `ContributionAnalysisService` finds commits and touched files for the requested author/time window, then the investigation tools are restricted to those files. The prompt policy says: `Only make claims supported by files touched by the requested author.`
